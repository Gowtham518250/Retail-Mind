TABLE: whatsapp_orders


PURPOSE: Orders received through WhatsApp and shared with the shop system, including message content, parsed items, status, and order value.

RELATIONSHIPS:
- shop_id scopes the order to a shop account; it references user_details.id.
- No customer or invoice foreign key is declared; sender_number and parsed_items_json are stored on this row.

COLUMNS:
- id (integer, primary key): WhatsApp order ID.
- shop_id (integer, required): Shop/owner reference; apply authenticated shop scope.
- sender_number (string, nullable): Sender's WhatsApp phone number.
- raw_text (text, required): Original incoming order text.
- parsed_items_json (text, nullable): Parsed order items in JSON form.
- status (enum, default PENDING): PENDING, ACCEPTED, COMPLETED, REJECTED.
- total_amount (numeric 10,2, default 0): Parsed/recorded order total.
- created_at (datetime): Order creation timestamp.
- updated_at (datetime): Last update timestamp.

QUERY GUIDANCE:
- Order count/status: COUNT(*) filtered by status and shop_id.
- Order value: SUM(total_amount), filtered by requested period and shop_id.
- Date questions normally use created_at; status changes have updated_at but no status-history table is represented here.
- Parse parsed_items_json only for item-level requests. Protect sender_number and raw_text as potentially sensitive customer data; avoid including them in aggregate answers.

RETRIEVAL TERMS: WhatsApp order, whatsapp, chat order, message order, sender, pending, accepted, completed, rejected, parsed items, order amount.

EXAMPLE QUESTIONS:
- How many WhatsApp orders are pending?
- What was the value of completed WhatsApp orders this month?
- Show the items parsed from a WhatsApp order.
- Which WhatsApp orders were updated recently?
